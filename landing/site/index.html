The human problem

Long cases are hard in the same six ways.

You are probably tired, you probably have no legal background, and you are doing this alongside the rest of your life.

Scattered documents

Letters are spread across inboxes and paper.

No shared memory

Nobody remembers what happened when, and why.

Deadlines that start on receipt

Many deadlines run from the day you received a letter, and are easy to lose track of.

A denial you cannot act on

It says something is missing, but not in a form you can act on.

The same story, again

You tell it again and again, and pay a lawyer to read the file first.

Doing it for someone else

It adds the fear of making a mistake.

If this sounds familiar, you are not doing it wrong. It is genuinely hard.

Who it helps

Built for the person holding the paperwork.

The one principle

Verifiable trust.

An AI that just says things does not help someone who is afraid of being wrong. So every claim is shown the same way.

1 · Claim

The appeal must be filed within 60 days of receiving the notice.

2 · Quote

“You have 60 days from the date you receive this notice to file an appeal.”

3 · Source

Decision from the State Disability Agency

Oct 14 · Page 2

Checked against the document

The model must quote the document, word for word.

No paraphrase counts as evidence.

Then the server checks the quote.

It looks for it in the document text. Case, quote marks and whitespace are ignored. The result is either “Checked against the document” or “Could not be checked. Check yourself.”

Dates are calculated by code, not by the model.

The model only reports the duration (“6 weeks”, “60 days”) and what it runs from: receipt, or the letter's date. The code adds it to the date you enter.

When a date is not in the document, it says so.

A date the model gives that appears neither in the document nor was computed by code is marked “The date is not in the document”, in an amber box.

It asks instead of guessing.

If a deadline depends on when you received the letter and you have not entered that, the app asks you.

What the check proves, and what it does not

It confirms the quote is in the text that was read.

It does not confirm the text was read correctly from a photo. That is what the review step is for. It does not confirm the model's interpretation of the quote is right. And drafts are not verified quote by quote.

Reading a letter

Photos are reviewed next to the extracted text. Dates, amounts and case numbers are flagged, because a wrong date gives a wrong deadline.

  • You can read, edit or delete the extracted text.
  • Each document shows a status: Read or Needs review.

Voice notes, labeled honestly

Muse Voice Transcribe turns the recording into text. You check and correct it before saving. The audio is not stored, only the text you save.

Checked against your voice note

“They said the statement must arrive by December 5.”

From your voice note, not an official document.

The analysis is told to treat a voice note as your account, never as an official decision, and to say that a deadline from a call should be confirmed in writing.

Built with Meta models

Two Meta models, each doing one clear job.

Muse Spark 1.3 reads, understands and writes. Muse Voice Transcribe 1.0 turns speech into text.

TaskModel and how
Read a photographed letterMuse Spark 1.3 vision. Transcribe word for word, and write [illegible] instead of guessing.
Read a scanned PDFMuse Spark 1.3, with the whole PDF as a file part.
Suggest title, type and dateMuse Spark 1.3, returning JSON.
Analyze the caseMuse Spark 1.3, three parallel calls: (a) summary, status and timeline; (b) deadlines and next steps; (c) what is missing and a glossary. Each returns JSON with quotes.
Answer a questionMuse Spark 1.3: an answer plus sources, each checked like any other claim.
Draft an appeal or handover summaryMuse Spark 1.3, plain text.
Turn a voice note into textMuse Voice Transcribe 1.0 through its file API.
Tested, not shipped

SAM 3.1

We tested it properly. It found the sheet of paper in a photo exactly, but cropping to it did not improve reading accuracy.

A segmenter finds objects, not the content of text, so it cannot safely power redaction. We did not use it, and our ID-number hiding says what it can miss.

Tested, not shipped

Quote locations on the photo

We asked Muse Spark for the location of a quote on the image. Its bounding boxes were on the wrong line.

So quote highlights appear in the extracted text, not drawn on the photo. Saying no to a feature we could not verify is part of the product's point.

Privacy and limitations

Honest about what it cannot promise yet.

That honesty is part of the product, not a footnote.

What happens to your data

  • Text and images are stored on the server and sent to Meta's models when read, analyzed or asked about. Use fictional or anonymized documents until you are sure you want to share real ones.
  • The API key stays on the server and is never sent to the browser.
  • Voice recordings are not stored, only the text you save.
  • Deleting a case removes all its documents, images, ticks and analysis.

What it cannot promise yet

  • No legal advice. Case Ally organizes and explains.
  • No sign-in yet. Anyone with the case link can see and change the case, and the interface says so. Real accounts are the first thing a real product would need.
  • ID-number hiding is pattern matching, not a guarantee. The handover page has a “Hide ID numbers” switch, and says so on the page.
  • Meta's data terms for API input and EEA storage requirements have not been reviewed. Do not use real sensitive data until that is done.
  • All sample documents are fictional.
